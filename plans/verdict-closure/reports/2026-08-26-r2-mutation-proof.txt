================ A PROCEDURAL TRAP THIS RUN WALKED INTO, RECORDED ================

`git checkout -- <file>` is the wrong way to revert a mutation while the real fix is still
UNCOMMITTED. It restored UdpTransportServer.cs to HEAD and took the actual X-36 edit with
it, and the only thing that noticed was the full-suite run going red on a test that had
passed minutes earlier. The mutation looked reverted; the feature was gone.

Do it in this order instead: commit the fix, THEN mutate, THEN `git checkout --`. For an
untracked file (ClientSeatRequester.cs was one) `git checkout` cannot restore anything at
all and says so quietly — the mutation has to be undone by hand, and re-run the gate
afterwards to prove the undo landed rather than assuming it.
