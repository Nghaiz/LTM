X-19 — mutation proof for NetMovementAgent.CharacterMove's collision-bypass detector
====================================================================================
2026-08-23. Unity 6000.3.21f1 EditMode, filter
Ironfront.Net.Unity.Server.Tests.CollisionBypassTests.

Per mutate-every-gate: a test is unverified until the real artifact has been broken and
the test seen going red, once per fault it claims to catch. Three faults are claimed, so
there are three mutants.


WHAT IS BEING GUARDED
---------------------
    public Vector3 CharacterMove(Vector3 delta)
    {
        CharacterController controller = Controller;

        if (controller != null && controller.enabled)
        {
            LastCollisionFlags = controller.Move(delta);
            return transform.position;
        }

        CollisionBypassedMoves++;
        LastCollisionFlags = CollisionFlags.None;
        if (CollisionBypassedMoves == 1) Debug.LogError(...);

        transform.position += delta;
        return transform.position;
    }

The uncollided branch is not new and is not removed -- a body whose controller is gone
still has to go somewhere. What is new is that it says so. Before this, it returned
`transform.position` exactly as the collided path does and left `LastCollisionFlags`
holding the previous real move's answer, so eleven thousand uncollided moves in one
lane-B run were indistinguishable from eleven thousand good ones.

MUTANT 1 — the counter counts everything
-----------------------------------------

A detector that fires on healthy moves is not a detector; a lane-B run graded on
"CollisionBypassedMoves == 0" would then fail on a perfectly good client, and the grade
would be discarded rather than the code.

-----------------------------------------------

No counter, no log, no cleared flags. This is the code that shipped, and the code X-19
was invisible in for three runs. It is the mutant that matters most: it asks whether the

A FOURTH FAULT WITH NO MUTANT, SAID OUT LOUD
---------------------------------------------
The null arm of `controller != null && controller.enabled` -- no CharacterController at
all -- has no test. `NetMovementAgent` declares
`[RequireComponent(typeof(CharacterController))]`, so Unity attaches one the instant the
agent is added and then REFUSES `DestroyImmediate` on it. The state is unreachable from
a test rather than untested by choice, and the comment in the fixture says so at the
place a reader would otherwise assume an oversight.


A SETUP ASSERT THAT IS ALSO A GATE
-----------------------------------
`ABypassedMoveDoesNotLeaveStaleCollisionFlags` asserts its own precondition before the
thing it is testing:

    Assert.AreNotEqual(CollisionFlags.None, agent.LastCollisionFlags,
        "Setup did not produce a collided move, so this test cannot tell a cleared flag
         from a flag that was never set. Fix the floor, do not weaken the assert.");

The first draft had no floor under the body, so the "real" move landed in empty space and
returned None -- and the test would have passed for the wrong reason, forever. It was
caught because the first run of the suite was RED for that reason and was read rather
than patched around.


VERDICT
-------
Three faults claimed, three mutants, three reds. Mutant 1 is caught by the healthy-body
test and mutant 3 by the flags test, each by the test written for it and by no other.
Mutant 2 -- a straight revert -- is caught by two of the three and NOT by the healthy-body
test, which is the discriminating fact: a suite of that test alone would have graded the
original bug green.

Code restored and re-run green before commit: CollisionBypassTests 3/3, whole EditMode
suite 49/49.
