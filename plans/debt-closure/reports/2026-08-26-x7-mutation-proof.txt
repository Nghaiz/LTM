The defect
----------
`Allocate` chose with `server.CpuPercent < best.CpuPercent`. Every real game server reports
`cpuPercent: -1` on purpose — `ServerMasterReporter.Update` says why: "Unity exposes no portable
process-CPU counter, and a fabricated number on a matchmaking input is worse than an absent one —
the master would sort servers by it." With every candidate at -1 the comparison is false for all
of them, `best` never moved off the first one iterated, and allocation was decided by
`Dictionary` layout. E-8 decided to leave the sentinel at -1; that decision did not cover the
ordering, and a live matchmaking defect is what was left.

The fix orders by `AverageTickMs` ascending — the signal the same reporter comment names as real
and already sends — then by `ServerId` ascending as a documented, assertable tie-break.

The one that mattered — B was GREEN on the first attempt
--------------------------------------------------------
The first version of AllocationIsDeterministicWhenLoadTies registered three servers, tied their
tick times, and asserted the FIRST. That passes under both rules: `Dictionary` yields insertion
order while nothing has been removed, so the lowest id was also the first yielded, and "ascending
server id" and "whatever comes out first" were indistinguishable. Mutation B left it green — a
test that could not fail for the reason it was written (green-that-proves-nothing.md), and
precisely the shape AC-5 asks to be pinned against ("a test that fails when it degrades to
insertion order").

The rewrite makes the two orders DISAGREE, using the mechanism that produces the divergence in
production rather than a contrivance: `Dictionary` hands out insertion order only until something
is removed. `RemoveConnection` (a dropped game server) frees a slot, and the next registration
reuses it and lands at the FRONT of iteration. Three servers register, the first is dropped, a
fourth registers into the freed slot — iteration is now 4, 2, 3 while ascending id says 2. All
three then report identical tick times, so nothing but the tie-break can choose.

That is a long-running master's steady state, and a tie on tick time is the COMMON case at match
start, when every idle server reports the same number. So the tie-break decides most real
allocations, and a tie-break that silently equals "first one the dictionary yields" is the X-7
defect wearing a different name.
