## 2. Two pairs that were one defect each

**X-69 and X-71 are one missing line.** `IAiDriver.Suspend` sets `enabled = false` when a
connection claims a body, so `ServerPlayer` through `NetMovementAgent` is the single writer to
that position. Unity's `enabled` gates the engine's own callbacks and nothing else — which is
exactly why `BoatInput`, `CarInput`, `HelicopterInput`, `StartSeated`, `EndSeated` and
`AiWorkAllowed` each open with an explicit check. `Velocity` did not.

So on a claimed body it kept returning a real walk vector. That is **X-71** directly (the server
walked a player's body 518 m, monotonically, while its owner sent no input), and the same call
reaches `LocalAvoidanceVelocity`, which enumerates `squad.members` on a slot that is squadless by
design — **X-69**, 10,126 NREs in one 600 s soak. Late-onset because it needs a claimed, pathing,
squadless body, which is what accumulates as players join and leave.

**X-73 was hiding behind X-74, exactly as X-74's row predicted.** `IsCleanOfActorState` compared
`ActorIdsInUse` against 0 while the reset was deliberately told to retain Dustbowl's 41
scene-resident bots, so its ERROR fired at every round transition. Behind that permanently-false
first term, in a short-circuiting `&&` chain that answers one bool and names nothing, the
projectile id pool leaked for the life of the process.

The soak confirms the fix on the shipping map: **zero `match reset left state behind` lines** in
1,805 s, against a line that used to fire at every round boundary.

## 3. The three wrong diagnoses

### X-70 — falsified

**Filed as:** *"these two prefabs are simply unauthored."*

`quadbike`, `jeep` and `helicopter` carry `networkId` 2, 1 and 4, authored in `e641ea1` — the V3
commit that introduced the field — and `VehicleIds.TryGetKind` knows every id 1–5. By elimination
the refusal was always the **id pool**. P7 then confirmed the row "still live" without
re-examining the diagnosis, so it was investigated in the wrong direction twice.

**Why it was mis-read:** the log line offered two candidates and no way to choose, so a reader
took the one they expected. `ServerVehicleLifecycleSink` had counted the two apart the whole
time. `DescribeSpawnRefusal` now reports both counters plus the pool's own numbers.

**Still unknown:** *why* the pool exhausts. Dustbowl authors 14 spawners against `MAX_VEHICLES`
16, which `VehicleIdPool`'s own remark describes as two spare with a 5 s quarantine against a
16 s respawn. A run can now answer it.

### X-64 — lead ruled out, real anomaly found one checkpoint earlier

**Filed lead:** *"OBS-B is the only client listing a vehicle id 4… a duplicate or mis-keyed proxy
is worth ruling out first."*

Id 4 is on **all three** clients — driver and OBS-A one checkpoint later — at the pad the driven
vehicle left. It is the spawner's replacement.

The real anomaly is earlier and the row never mentions it: OBS-B read vehicle 15 at
`(2099.69, 13.53, 1159.40)` at `at-vehicle` against `(2097.36, 12.33, 1150.91)` on both others —
**9 m apart before anyone drove** — then jittered by centimetres and stopped. A dynamic body
settling and coming to rest, not an interpolator stalling.

**Cause:** `Vehicle.SetNetworkDriven` recorded a state it may have failed to apply. `rigidbody` is
cached in `Awake`; the replication layer binds its proxy at spawn; with the field unpopulated the
old code set `NetworkDriven = true`, skipped the `isKinematic` write, and its flag-only early
return made every later call a no-op. The method's own remark predicted the symptom before it was
measured: *"jitter that looks exactly like a network problem and is not. Nothing above this layer
can diagnose that, because every number on the wire is correct."*

### X-67 — cause unproven, and now provable

Reading the source found that **three** different failures all rendered as `RejectedTooFar` — an
unresolvable actor, an unresolvable vehicle, and a seat index with no `Seat` behind it. So P5's
four refusals at 3.70–4.27 m are equally consistent with any of four causes, and no artifact
records which. `RejectedNoSuchSeat` already existed, documented as *"No such vehicle, or no such
seat index on it"*, and was never sent from here.

The origin mismatch is fixed **by construction** — `GetSeatPosition` moved onto
`IGameplayVehicleBody`, implemented once, both ends calling it — but whether it was ever the cause
is still unestablished.

## 4. The soak that graded the wrong process

`p10-soak-01` ran its full 1,805 s and reported **30 minutes MET, no crash MET, leak FAILED at
35%/h**. Every one of those three verdicts was about a server that never started.

A stale server from an earlier session held UDP 27015. `NetServerBootstrap.StartServer` catches
the `SocketException`, logs an error, sets `_misconfigured` and **returns** — deliberately,
because an exception escaping `Awake` leaves a half-built server behind. So the process stayed
alive, `HasExited` stayed false, the playable client connected to that **older** process — a
build predating every fix under test — and the runner sampled the memory of a process doing no
work.

`HasExited` was the only liveness check. It now also asserts that **this run's** server owns the
port, because "something owns it" is exactly the state that produced the void run.

**Mutation-tested rather than argued.** A `UdpClient` was made to squat 27015 and the runner
re-run: it threw during warm-up and produced only `server.log` — no `memory.csv`, no `run.json`,
no verdict. Under the old code that same condition produced a full artifact set and a graded
FAILED.

This is the harness's own instance of the deployment check folded into `operations.md` earlier in
this same sweep, from the hand-off document P9 deleted: *"`Up` does not mean working. A container
`Up` with no port open is the failure that cost three days to find."* The soak had the same hole,
and nobody had looked because the soak had never been run.

### The re-run, `p10-soak-02` — VERDICT MET

| Clause | Result |

| 30 minutes | **MET** — 1,809 s of continuous play |
| no crash | **MET** — no crash marker in either log; both processes outlived the clock |

**Zero `NullReferenceException` and zero `match reset left state behind` in 1,809 s**, against
P7's **10,126** NREs in 600 s and an audit line that fired at every round transition. That is
X-69, X-71 and X-74 confirmed at runtime on the shipping map, which no unit test could do.

The 8 error lines the grader counts are all startup-time diagnostics, not runtime faults: one
config notice about `ACCEPT_UNSIGNED_TICKETS` being correctly ignored, and **three from P2's own
gate** — `RemoteActorView` writes the animator parameters `prone`, `aiming` and `pitch`, and the
`Actor` controller declares none of them, so each write is a silent no-op. P2 fixed the sliding
bodies by writing `movement x` / `movement y`; these three are a separate authoring gap that its
gate has been reporting and nobody has read. **Not filed as a ledger row by this session** — it
needs the animator controller open, which is authoring work, not a code change.

`p10-soak-01`'s artifacts are deleted rather than kept. A void run's artifacts are worse than
none: they are gradeable, they look complete, and nothing in them says which process they
describe.

## 6. What this sweep was actually about

Six of the nine closures are fixes to **reporting**, not to gameplay:

- `UncleanTerms` names every failing audit term instead of answering one bool.
- `DescribeSpawnRefusal` names the counter instead of offering two candidates.
- `RejectedNoSuchSeat` is sent where it was documented and never used.
- The lane-B aim block carries its own age, so a cached reading cannot pass as a live one.
- The minimap records what was asked **and** what happened, because a request that had no effect
  and a request never made render identically.
- The soak refuses to grade a server that never bound.

Every defect this session found by *reading* was found because some instrument could not
distinguish its own cases. That is the same failure as `green-that-proves-nothing.md`, arriving
six times in one day through six different doors — and it is why the ledger's three wrong rows
were wrong.
